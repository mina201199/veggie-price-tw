# 這菜貴不貴

一鍵查蔬菜水果現在貴不貴：用農業部過去五年的批發行情，判斷今天的價格和「往年同一時期」比起來是便宜、正常還是偏貴；太貴或非產季時，推薦同類當季又便宜的替代品。也可以輸入攤販開的價格，看看合不合理。

網站：https://mina201199.github.io/veggie-price-tw/
每天台灣時間 11:30、17:30 自動抓新資料並更新（GitHub Actions）。整理好的資料也可以直接拿：`https://mina201199.github.io/veggie-price-tw/data.json`

## 資料來源

- 農業部農業資料開放平臺「農產品交易行情」：全台果菜批發市場每日成交價與交易量（蔬菜、水果，含進口）
- 臺北市市場處「臺北市公有零售市場行情」：每月各品項平均零售價，用來推算攤販零售行情

## 方法

判斷「貴不貴」的計算都在 `tools/catalog.py`、`tools/build.py`、`tools/markup.py`；網頁（`tools/template.html`）只讀 `data.json` 裡算好的數字再套門檻。

### 每日價格：近 5 天依交易量加權的平滑價

- 全台各市場、同一個常用名底下各品種的成交，依交易量加權合併成每日均價。
- 每天的價格取「當天與前 4 天」中有交易日子的交易量加權平均，避免各市場休市、到貨組合不同造成的鋸齒跳動。網頁上的最新批發價就是這個平滑價。
- 最近 10 天沒有交易的品項視為非產季，不給目前價格；近兩年交易天數不到 10 天的品項不收錄。

### 往年同期基準（`tools/catalog.py` 的 `same_period_baseline`）

- 取前 5 年、每年「同一天前後 15 天」的平滑價，全部放在一起取中位數（2/29 在平年改用 2/28）。用中位數是為了不讓單一颱風年拉偏基準。
- 合計至少 20 天、而且至少 2 個年份有資料才算出基準；不夠就顯示「難判斷」，不硬比。
- 價格比 = 目前平滑價 ÷ 往年同期基準：≤ 0.88 為便宜、≤ 1.12 為正常、≤ 1.35 為偏貴，再高為很貴。

### 近一年百分位與供應量比（`tools/build.py` 的 `summarize`）

- **近一年百分位**：過去 365 天的平滑價裡，有多少比例的日子比目前便宜（至少 30 天資料才計算），並列出一年內最低與最高價。用來補充說明：價格比 ≤ 1.12 但百分位 ≥ 85% 時，提示「這時節本來就是它一年中比較貴的時候」；價格比 > 1.12 但百分位 ≤ 30% 時，提示「已經是過去一年相對低的價位」。
- **供應量比**：近 14 天的日均交易量 ÷ 過去一年的日均交易量（都只算有交易的日子）。低於 0.2 標示為非產季。
- 右側「現在當季・買了划算」只列國產、供應量比 ≥ 1.1、價格比 ≤ 1.0、近一年百分位 ≤ 75%，且交易量夠大（程式門檻 `vol >= 1500`）的品項。

### 攤販零售價參考（`tools/markup.py` 的 `model`、`_loo`，`tools/build.py` 的 `retail_estimate`）

- **配對資料**：臺北市公有零售市場每月各品項的平均零售價，對上農業部同月、依交易量加權的批發均價，單位都換成元／台斤（1 台斤 = 0.6 公斤）。
- **兩種估法**（每個品項至少 4 個月的配對才建模）：
  - 中位數倍數：零售 ≈ b × 批發，b 取各月「零售 ÷ 批發」的中位數。
  - 最小平方線性：零售 ≈ a + b × 批發。至少 8 個月才考慮，斜率必須為正；攤商有固定開銷，批發很便宜時零售不會等比例降。
- **留一交叉驗證挑模型**：每次拿掉一個月，用其餘月份預測它並計算相對誤差；線性的誤差中位數比較小才用線性，否則用中位數倍數。
- **合理區間**：估計值 ×（1 ± 驗證誤差中位數 × 1.5），寬度限制在 ±12%～±35%。
- **不外推**：估算時的批發價用近 14 天依交易量加權的均價（沒有就用目前價）；超出建模時看過的批發價範圍時，改用範圍邊界的「零售 ÷ 批發」倍數，不把直線延伸出去。
- **沒有自己的零售資料**：進口品項借用國產同品項的關係；其餘用同類別零售 ÷ 批發倍數的中位數，誤差以 25% 計，區間因此是上限 ±35%。
- **攤販開價判斷**：低於區間下限為「划算」、在區間內為「合理」、高於上限 20% 以內為「偏貴」，再高為「太貴」。

## 應用大框架

面向料理新手與家庭採買者，降低查詢行情與整理採買紀錄的負擔。

| 模組 | 概述 | 階段 |
|---|---|---|
| 行情查詢 | 整理政府公開農產品行情，提供查詢與比較入口 | 既有網頁 |
| 個人採買紀錄 | 記錄商家、商品與購買歷史 | 本機原型，未公開部署 |
| 互動探索 | 探索適合行動裝置的互動介面 | 本機原型，未公開部署 |

```text
使用者介面
    ↓
應用功能層（查詢與紀錄）
    ↓
資料處理層（格式、時間與單位管理）
    ↓
資料來源／儲存層
```

以上為概念責任分層，並非已部署的完整後端。
行情網站採靜態頁面與自動化更新；其他原型尚未整合為正式手機 App。
個人紀錄目前只存在使用者瀏覽器，尚無帳號與雲端同步。
批發行情不等於個別店家的即時零售價，也不代表商品品質保證。

## 本機執行

需要 Python 3.10 以上，不用安裝任何套件。

```bash
python tools/fetch.py          # 抓最近 10 天批發行情，合併進 data/raw/ 月檔
python tools/fetch_retail.py   # 抓臺北市零售行情
python tools/build.py          # 算指標 → site/data.json
python tools/inject.py         # 產生網頁 → site/index.html
python -m unittest discover -s tools   # 測試
```

## 檔案

| 路徑 | 內容 |
|---|---|
| `data/raw/YYYY-MM.json` | 每月的批發行情（依品種、日期），每天自動更新當月檔 |
| `data/retail_taipei.json` | 臺北市公有市場月均零售價 |
| `tools/fetch.py` | 抓農業部 API（處理單次 9999 筆上限、憑證相容問題） |
| `tools/build.py` | 行情資料整理 |
| `tools/catalog.py` | 官方品名對常用名與分類、往年同期基準（各頁面共用） |
| `tools/markup.py` | 行情參考資訊處理 |
| `tools/template.html` | 網頁介面 |
| `.github/workflows/update.yml` | 每日自動更新與發布 |
