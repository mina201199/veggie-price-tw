## 2026-10-14 採買流程更新

固定私人 Sites 的採買首頁、筆記與待買清單現在使用同一個 ChatGPT 帳號。待買清單存在 D1，可跨裝置同步；只有成功記筆記才移除同名待買項目，取消或儲存失敗會保留。原始碼靜態預覽仍使用本機模式，Django `/app/` 仍是另一套帳號與本機清單，不混用資料。

測試與部署記錄見 `docs/operations/2026-10-14-batches.md`，實機待驗收見 `docs/operations/mobile-acceptance.md`。匯出私人筆記備份若發現引用照片遺失會停止；帳號筆記／R2 引用照片／清單的完整邏輯備份與隔離還原已驗證；全系統物理備份另列維運工作。

## 整合 3D 採買城市（2026-10-13）

主 App 只有一個「3D 採買地圖」：以真實道路與建築輪廓生成市容，角色在同一張地圖跟隨 GPS。總覽按鈕拉遠看街區，再按回到跟隨，不再把角色漫遊和地圖分成重複頁面。舊 `view=map` 連結會進入同一個 3D 畫面。另外保留今日菜價與採買筆記。

大園／中壢預覽可在地區選單切換，預覽不代表 GPS 所在位置。GPS 第一筆有效定位會直接放到使用者實際位置，後續短距離平滑跟隨，大幅移動直接校正。戶外 GPS 模式搖桿暫停，手動預覽可沿道路試走、示範沿來源道路走到採買入口；不可把這個示範當實際導航。

地理資料：`city-data/dayuan.json` 和 `city-data/zhongli.json` 為 2026-10-13 OpenStreetMap／Overpass 快照。大園 1,203 條來源道路、236 個建築輪廓、2 個市場與 3 家超市；中壢 5,261 條來源道路、10,468 個建築輪廓、8 個市場與 54 家超市。渲染和地點清單只使用角色周圍街區，不代表兩個行政區的完整官方店家名錄。命名店家與座標均來自來源，不虛構採買地點。

建築輪廓已有資料時立體化；缺少高度採示意樓高。部分街區缺少建物輪廓，在真實商店附近補少量示意街屋，介面有清楚標示。店面招牌、示意入口與室內配置不宣稱實景還原。市容、店家清單、街區資料可用性和定位精度是不同限制。

GPS 街區沿用既有市場街景的磁磚牆、窗框、陽台欄杆、冷氣、騎樓柱和條紋遮棚；附近道路側立面分段補外觀，最多 160 段，合併細節減少手機繪製負擔。遠處建物保留簡化輪廓。跟隨視角降低為街道視角，載入街區／手動移到入口時朝道路方向；總覽仍可查看街區。店面示意模型退到路旁，入口定位圓圈保留來源道路上的位置。

畫面邊緣顯示目前街區圖資收錄的所有市場（角色周圍約 1 公里），依直線距離排序；不是全市完整名錄。箭頭指向市場來源座標，與示意入口分開；東西南北標記及箭頭隨實際鏡頭方向轉動，距離隨角色位置更新。點市場標籤只選取地點，不傳送 GPS 角色。市場較多時邊緣清單可捲動；室內與換角色時隱藏。手機單指拖曳／旋轉按鈕可連續旋轉 360 度，雙指縮放。

市場／超市以專屬招牌、顏色與入口圓圈識別。戶外角色距示意入口 25 公尺內可進店；GPS 模式不可遠端傳送進店。手動模式可從「附近市場／超市」選地點，按「移到入口試逛」做示意探索。市場有攤棚／攤商，超市有貨架／生鮮分類，室內可拖搖桿行走，走近互動圈或直接點分類。

店內可收藏探索品項卡、讀取真實果菜批發行情（顯示交易日；不是分店售價或即時庫存），自行輸入現場價格並保存採買筆記。固定網址沿用 ChatGPT 登入身分，筆記與修訂歷史存在帳號專屬 D1 文件、私人照片存在 R2，手機與電腦登入同一帳號即可同步。儲存成功才關閉編輯器；返回筆記頁、切回前景或可見時每 30 秒更新，也可手動重新同步。樂觀版本檢查合併獨立新增及相容歷史；同筆不同修正會提示衝突，斷線保留表單，不宣稱已同步。原有 localStorage 筆記需由使用者按「將本機筆記加入目前帳號」確認匯入，原資料保持不變；本機／Django 預覽没有同網址雲端 API 時沿用原本本機儲存。請定期匯出完整備份。戶外 GPS 在進店期間仍維持；返回時以最新有效戶外座標還原，不用室內虛擬座標覆蓋 GPS。GPS 不寫入帳號。

固定網址的帳號服務使用 Sites 支援的 Vinext Worker／D1／R2（`hosted/gps-map/` 的獨立來源儲存庫），不是 Python Django 在 Sites 執行。原 Django 帳號後端仍保留作獨立部署；兩套帳號資料不自動互相遷移。雲端 JSON 筆記上限 5 MB，每张縮小後照片上限 6 MB；寫入與照片請求綁定登入帳號與原帳號 ID，伺服器只使用平台驗證身分。

台灣各縣市（含離島）可定位，排除宜蘭、花蓮、台東、南投。大園、中壢初始測試範圍使用內建快照；其他地區／範圍外位置按需從 Overpass 載入小街區，其可用性無保證，失敗會提示並保留定位，不能宣稱全台 3D 資料已全部驗證。無須全台預抓或下載圖磚。

GPS 精度超過 60 公尺、超過 15 秒的定位或範圍外位置不移動角色；微小抖動低於 2–6 公尺時保留原位置。位置不吸附道路；手動探索才限制在道路並避開建物。背景暫停定位，返回後重新取得新定位。縣市範圍使用 2012 年簡化 `taiwan-counties.json`，海岸／縣界附近可能有誤差，見原始 [邊界來源](https://github.com/ronnywang/twgeojson)。外部地理來源會收到所請求的街區範圍，GPS 本身不由本應用持久保存。

## 一趟採買：行情 → 現場比價 → 筆記

`prices.html` 現在可直接作為採買首頁，不再強制轉入城市外框。抽屜預設半開，保留貓咪互動；首頁提供待買清單、由既有筆記整理的常買食材，以及使用原有 `Prices.bestDeals` 規則的近期划算食材。清單也可手動加入沒有行情的商品，例如雞蛋與牛奶。

點食材查看行情，輸入店家的總價與重量，可對照零售估計及自己的上次購買紀錄。歷史比較先換算相同重量或數量單位，缺重量或不同非重量單位時不判斷漲跌；也會提示日期、地點、已填規格與促銷條件。行情超過七天時不提供目前零售判斷。

「買了，帶入採買筆記」將商品、現場價格、重量與品種帶入表單，不自動儲存。確認購買地點並儲存成功後，才從清單移除同名商品；取消、欄位錯誤或儲存失敗都保留清單。清單中的「買了，記一筆」也支援沒有行情的商品。筆記頁頂部可返回行情首頁，下次會顯示常買商品與自己的購買紀錄。

本機清單存在 localStorage `veggie-shopping-plan-v1:local`，沿用既有私人筆記。登入版由 `/app/` 開啟行情時讀取目前帳號的後端筆記，儲存回登入版帳本；清單依帳號 id 分開，但仍只存在這台瀏覽器，不會跨裝置同步。交接內容暫存在同一分頁的 sessionStorage，不放入網址，也不自動分享價格。另一分頁切換帳號後，返回行情頁或執行私人操作會重新確認帳號並清除舊私人畫面。

驗證：`node prototype-3d/shopping-flow.test.cjs`、`node prototype-3d/shopping-flow.browser.test.cjs`、`node prototype-3d/shopping-account.browser.test.cjs`。瀏覽器測試可用 `PLAYWRIGHT_MODULE` 指定 Playwright，使用 Edge、獨立瀏覽器環境和獨立測試資料庫，不改使用者資料。

## 永和 3D 採買街區（index.html）

今日菜價底部「3D 採買地圖」進入原本角色場景，網址 http://localhost:8877/index.html。永和街道取自 OpenStreetMap，經緯度以公尺投影到 3D 平面。下拉選擇地點，按「移到附近」後用搖桿或「往入口走」抵達入口，進店探索。兩座市場使用攤位模型，七家超市使用貨架模型。建築輪廓取自公開地圖；缺少高度時使用示意樓高，外觀、門口、室內、商品均非實景還原。

`yonghe-streets.js` 是 OpenStreetMap 街道及建築輪廓的本機快照，資料遵循 ODbL，來源 https://www.openstreetmap.org/copyright。`yonghe-3d-world.js` 建立場景與地理位置，保留可見來源標示。3D 場景不需要即時地圖服務。`yonghe-map.html` 保留為平面總覽，每個地點的「在 3D 地圖試逛」連到相同地點附近。

首批資料於 2026-10-08 核對：溪洲與永安兩座公有市場，加上全聯官方頁面提供的七間永和分店。全聯名稱、地址、營業時間和經緯度取自官方門市頁；市場地址、營業時間取自新北市政府市場處，市場位置取自 OpenStreetMap。`yonghe-places.js` 保留逐筆來源與核對日期。首批資料尚不包含所有超市品牌與民有市場，因此不推算完整店家密度或宣稱全台第一；市場也不把各攤位重複計入據點數。

底圖使用 OpenStreetMap 標準街道圖，需網路連線，保留可見來源標示並依瀏覽器快取；不預抓或批次下載圖磚。地圖套件固定 Leaflet 1.9.4，本機存於 vendor/ 並附授權。底圖暫時無法載入時仍可使用地點清單。尚未串接 GPS、即時營業、庫存或零售價格。

`node prototype-3d/yonghe-map.browser.test.cjs` 驗證實際 Edge 瀏覽器的底圖、地點與清單篩選、搜尋、詳情、導航、手機排版和底圖失敗情境。沒有本機 Playwright 時可設定 `PLAYWRIGHT_MODULE`，Python 執行檔可由 `MAP_TEST_PYTHON` 指定。

## 私人採買筆記（本機版）

城市左側「採買筆記」或 `notebook.html` 可直接使用，不必進行 3D 探索。支援商品、品牌、分店／攤位、規格、日期、價格、重量、促銷、私人心得、搜尋、再次購買、修訂歷史與 JSON 備份匯出。按重量換算公斤價，不推測每顆／每包的重量。

資料存於同一來源瀏覽器的 localStorage `veggie-shopping-notes-v1`，不是登入帳號、加密保險箱或雲端同步；共用裝置可被他人看到。清除瀏覽器資料會遺失，應定期匯出。localhost 與 127.0.0.1 是不同來源，資料不共用。儲存失敗不顯示成功，讀取毀損資料時停止寫入，可匯出原始內容。編輯會保留舊版私人內容於歷史中；目前沒有刪除／匯入復原介面。

「願意分享價格」目前只記本機意願，並展示白名單欄位，不上傳、不送審、不核發點數。未來正式串接必須重新確認授權，不能自動送出既有筆記。LLM 辨識尚未接入。執行 `node prototype-3d/notes.test.cjs` 驗證儲存、修訂、隱私與單位規則。

「📷 拍收據／標價」可以拍照或選一張照片，對照照片手動輸入店家、日期和品項；收據有多項時可加多列，勾選的每一項各存成一筆筆記，全部共用這張照片。照片在本機縮成長邊 1568 px 的 JPEG，存進這台瀏覽器的 IndexedDB `veggie-shopping-photos`，筆記只記照片 id 與類型（收據／標價／其他），不上傳。筆記詳情會顯示照片，可「從這張照片再記一項」；修正會保留照片，「再買一次」不沿用舊照片。匯出備份會一起帶走照片（data URL），匯入時先檢查照片格式與大小，再交給原本的筆記匯入檢查；這台裝置已有的照片不重複加入。「🤖 自動辨識」按鈕已預留但未啟用：之後的辨識器只要回傳 `{ venue?, date?, items: [{ product, price, quantity?, unit? }] }`，填進品項列讓使用者確認，不會自動儲存。執行 `node prototype-3d/photo-notes.test.cjs` 驗證照片欄位、多項一次儲存與備份。

從專案根目錄執行 `python -m http.server 8877 --bind 127.0.0.1 --directory prototype-3d`，開啟 http://localhost:8877。

拖曳搖桿或使用 WASD／方向鍵走動；拖曳場景、旋轉按鈕調整鏡頭。先選地點並按「移到附近」，「往入口走」沿附近道路示範前往市場。抵達入口後才能進入，市場使用攤位層級，其他通路使用分店品類層級。碰撞阻擋穿入建築。

角色、建築、樹木與攤棚為原創程序化幾何模型；使用固定版本 Three.js 0.160.1（MIT，vendor/three.min.js）。可離線載入，不需 CDN 或外部帳號。

抵達後進入可行走的 3D 室內：市場有攤棚、攤商和商品；連鎖分店有貨架和生鮮檯。走近金色圓圈即可看商品、收集品項卡或模擬送審。卡片及待審狀態保留於這次頁面工作階段，刷新即重置，沒有實際點數交易。「帶我逛攤位」示範沿走道前往下一站；出口或「返回城市」可離開。

「換角色」有 11 個角色：市場人物圖鑑的 8 位（`figure-kit.js`、`figure-cast.js`，與 figures.html 同一套模型）和三隻貓。預設是買菜阿嬤。角色選單有 3D 預覽，可以看正背面、試走幾步，選好後城內和室內的角色會一起換掉。人物走路由 `FigureKit` 自己的步態驅動，拿著菜籃車或拐杖的那隻手不擺動。選擇存在本機 localStorage 的 `veggie-avatar-v1`，不傳送到外部服務；若存的是已移除人物（修車師傅、外送員、烤肉攤老闆、自助餐阿姨）或舊角色（小小探險家、草莓兔兔、蜂蜜熊熊、奶茶貓貓、青蛙雨衣、四款娃娃，已移除），會改回預設。儲存不可用時仍能換角色。

衣櫥裡的三隻貓「歐巴」「波妞」「小橘」使用 `cat-kit.js` 的毛皮模型（與首頁 prices.html 的貓同一套），`cats.js` 只負責包裝：城內用四腳步態走路，停下約 4 秒會坐下，頭會轉向鏡頭；衣櫥預覽另建一隻，可以試走。毛皮在城內透過只寫入陰影圖的替身網格投影。執行 `node prototype-3d/cats.test.cjs` 驗證尺寸、站地與轉頭。

此為手機比例的瀏覽器原型，不是已打包的 Android/iOS App。街道與地點使用永和真實資料；建築外觀與室內為示意，並非真實店面還原；價格、點數皆為示意。距離為入口直線估算，並非導航路程。尚未整合 GPS、照片、AI 驗證、多人資料庫、訂閱或點數交易。照片位置保留為明確佔位，沒有偽裝成真實攤位照片。

## 首頁：貓咪帶路＋今日菜價（prices.html）

開啟 http://localhost:8877/prices.html（啟動器預設開這頁；舊的 cats-demo.html 會自動轉過來）。上方是 3D 場景（`cat-guide.js`），下方抽屜是今日菜價（`prices-ui.js`，`drawer.js` 控制收起／半開／全開），底部導覽到採買筆記與城市探索。

黑貓歐巴、灰白虎斑波妞與橘色虎斑小橘依參考圖重新建模：大頭短腿的幼貓比例、shell 著色的毛皮（`cat-kit.js`），會眨眼、抖耳朵、甩尾巴，有站、走、坐、翻肚四種姿勢。拖曳轉鏡頭，雙指或滾輪縮放；搖桿、WASD 或點地面讓貓走過去。六個菜籃顯示 `prices-data.json` 裡該菜今天成交量最大的國產品種；走近時的價格卡可點開 30 日走勢。按「帶我找今天最划算的菜」或點公佈欄，貓走到公佈欄前，抽屜半開列出前 10 名（`Prices.bestDeals`：最新交易日、國產、成交量 ≥ 3,000 公斤、比往年同期便宜，同名只留一個品種）。在抽屜查看某樣菜的詳情後，若場景有那一籃，貓會走過去說出判斷。讀取失敗時菜籃與公佈欄顯示「—」，不使用示範數字；瀏覽器不支援 WebGL 時只收起 3D，菜價清單照常可用。

`CatKit.create(THREE, 'blackcat' | 'mochi' | 'ginger', { shells, castShadow })` 回傳 `{ root, setState, update, meow }`，可以直接放進其他 Three.js 場景；`update(dt, { speed, look })` 的 look 是世界座標，貓放在別的物件裡也能正確轉頭。`node cat-kit.test.cjs` 檢查三隻貓在每個姿勢都站在地面上。手機預設 12 層毛、電腦 20 層，畫面太慢時會自動降解析度。

## 市場人物圖鑑（figures.html）

開啟 http://localhost:8877/figures.html。依使用者核定的 8 位角色設定圖，用程式碼建出的公仔風 3D 角色：買菜阿嬤、里長伯、散步阿公、菜市場阿姨、汗衫阿伯、家庭主婦、幼稚園小朋友、八酒。每位站在白色展示台上，可拖曳旋轉、滾輪或雙指縮放，有正面／側面／背面三個視角與自動旋轉；「全員」把 8 位排成兩排（後排站在台階上），點任一位可切回單人。卡片縮圖在載入後逐一渲染。

`figure-kit.js` 是共用骨架與零件：約三頭身的身體比例、畫在頭上的臉（眼睛、眉毛、嘴型、腮紅、皺紋、鬍渣、髒污）、上衣／背心／褲子／九種鞋、毛巾、皮帶、佛珠，以及程式畫的布料圖案（碎花、格紋、條紋、小熊印花等）。`figure-cast.js` 放每個角色獨有的髮型、帽子與道具，並用 `FigureKit.define(id, spec)` 註冊。`FigureKit.create(THREE, id, { castShadow })` 回傳 `{ root, update, height, dispose }`，可以直接放進其他 Three.js 場景。`node figure-kit.test.cjs` 檢查 8 位都能建出、站在地面上、高度合理。

3D 整合驗證：`node prototype-3d/yonghe-3d.browser.test.cjs`（預覽伺服器須位於 localhost:8877；測試需 Playwright 與 Edge），涵蓋地點選擇、抵達、進店、返回和深連結。
